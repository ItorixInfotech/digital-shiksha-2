# RCA — predictor/unlock "step 2 fails when phone is typed, no PDF"

Deployment: digital-shiksha-2 (digitalshikshaonline.com / digitalshiksha.in)
Active run: ba49120c-6475-414b-a98a-3ae35d826d1f (redeploy, live; the new `find_by_phone` diagnostic line IS live)

## Verdict
Phone matching is NOT the failing step — it works. The **amount check rejects the genuine payment** because the configured MHT CET fee (₹1500 / 150000 paise) is ₹1 higher than what the Razorpay Payment Page actually charges (₹1499 / 149900 paise), and the amount window has **no downward tolerance**. Result: every phone-based unlock for MHT CET returns HTTP 404 and no PDF is generated.

### Source proof (backend/lib/razorpay.py)
```python
PAID_EXAMS = {
    "MHT CET": (150000, "https://rzp.io/rzp/6wXdLUk"),   # ₹1500 engineering  <-- configured fee
    "MHT CET Pharmacy": (59900, ...),                     # ₹599
    ...
}
def _amount_ok(amount, fee):
    return isinstance(amount, int) and fee <= amount <= fee * 105 // 100
```
For MHT CET the accepted window is `[150000, 157500]`. The real captured payment is **149900**, which is `100` paise **below the lower bound**, so `_amount_ok` returns False → `mine` is empty → `PaymentError(404, ...)`. The 5% tolerance is only *upward* (for Razorpay convenience fees); there is no allowance for a payment that is slightly *below* the configured fee. The Payment Page https://rzp.io/rzp/6wXdLUk is charging ₹1499, but the code expects ≥₹1500.

### Why MHT CET Pharmacy works but MHT CET doesn't
The 3 successful unlocks in Mongo are all **MHT CET Pharmacy, amount ₹599** (fee 59900 — exact match) and all carry a real `payment_id` (direct payment_id lookup path, not phone). The broken flow is specifically MHT CET engineering via phone, where 149900 ≠ the 150000 floor.
